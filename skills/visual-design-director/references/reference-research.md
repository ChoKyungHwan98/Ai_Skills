# Reference research

Use this when a supplied reference needs interpretation or the task would benefit from finding one. Do not ask a user who lacks design vocabulary to assemble a mood board.

1. Name the decision to resolve (for example, first-screen emphasis, analytical comparison, case-study order, or slide narrative). Select one or two close examples; add a contrasting example only when it exposes a useful tradeoff.
2. Inspect the actual page, screen, article, or rendered deck. Record **observed feature → working mechanism → fit to this artifact → adaptation boundary**. Separate observation from an inference. If the surface is behind a login or only a marketing page is visible, do not describe the hidden product UI as inspected.
3. Prefer the original creator, official documentation, or an accessible real product over a gallery thumbnail. Check current URLs when using them; examples can change. A source is evidence for a particular treatment, not an instruction to copy its brand or a universal style rule.
4. Offer a recommendation in ordinary language. The user can respond with “too strong,” “too plain,” or a marked region; they need not name an aesthetic movement.
